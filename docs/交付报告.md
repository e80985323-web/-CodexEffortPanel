## 1. 这是什么

把之前散落在命令行里的「思考强度相关修改」整合成**一个双击即用的图形面板**。

面板本身**不做任何新事情**——它只是把已有的、版本无关的补丁引擎
`%LOCALAPPDATA%\CodexEffortPanel\codex-max-effects-patch.py` 包了一层界面：
**读状态** + **一键执行** + **启动 Codex** + **回退**。

四项能力（也就是面板上那 5 行状态）：

| 行 | 名称 | 做什么 |
|---|---|---|
| 1 | 模型目录 max 档位 | 让思考强度滑块能拉到最高档（4 个模型都补上 `max`） |
| 2 | 强度白名单 | `config.toml` 的 `[desktop] enabled-reasoning-efforts` 含 `max`（共 7 档） |
| 3 | 紫光特效 | 拉到最高档时，滑块填充由**蓝变紫**并出现粒子/爆发特效 |
| 4 | Ultra 标签 | 最高档的显示文字由「最高」改成 **Ultra**（仅中文 zh-CN） |
| 5 | 包身份补丁 | 支撑 3、4 的底层补丁（跳过 MSIX 包身份调用，使可写副本能启动） |

## 2. 怎么用

**双击桌面上的「Codex 思考强度」**（`桌面\Codex 思考强度.lnk`）。

- 打开后面板会自动加载引擎并刷新一次状态，**大约 1 秒**。
- **不会弹黑框**：快捷方式指向 `C:\Windows\pyw.exe` 执行 `.pyw`，走的是无控制台宿主。
- 状态行**全绿**＝四项修改都已生效。

### 四个按钮

| 按钮 | 行为 |
|---|---|
| **刷新状态** | 重新读一遍 5 项状态，只读、不改任何文件 |
| **一键生效** | 跑一次补丁引擎（必要时重建可写副本），把 5 项都打上 |
| **启动 Codex** | 先执行「一键生效」，再用**外接 API 代理**启动 Codex（读启动器里的 `PROXY`） |
| **回退** | 把**当前这一个版本**的可写副本还原成原始文件（有二次确认弹窗） |

> 「一键生效」与「启动 Codex」是分开的，所以你**不需要**为了打补丁而被强制启动 Codex。

## 3. ⚠️ 一个重要注意点：Codex 是单实例程序

**Codex 正在运行时，点「启动 Codex」不会让补丁生效。**

原因是 Codex 有单实例锁（`requestSingleInstanceLock`）：第二次 `start` 会被**转发给已经在运行的那个窗口**，
不会加载新代码。面板已经把这个情况做成了**显式提示**，而不是让你困惑：

```
-- 启动 Codex --
检测到 Codex 已经在运行（10 个进程）。
它是单实例程序：新启动会被转发到已有窗口，
窗口内容不会变化。要让补丁生效，请先完全退出 Codex。
```

**正确顺序：先完全退出 Codex → 再点「启动 Codex」**（或直接双击你原来的 `Codex(默认).lnk` 启动器，
启动器本身也会自动打补丁）。

## 5. 为什么是 `.pyw` 而不是打包成 `.exe`

**这是刻意的选择，不是偷懒：**

- 补丁引擎必须**随 Codex 版本更新而保持可编辑**。Codex 每次 Store 更新会换包目录名，
  引擎靠**正则现推**出该版本的补丁字面量（不硬编码）。如果冻结成 exe，引擎就被焊死在二进制里，
  以后想改就得重新打包——那是退步。
- 面板与引擎**同目录、运行时加载**，不复制一份，所以两者不会漂移。
- 零新依赖：只用 Python 标准库的 `tkinter`，本机已有 `Python 3.14.6` + `Tk 8.6` + `pythonw.exe`。
- 因此**没有引入 PyInstaller**，也没有新增任何需要维护的构建步骤。

---

## 6. 更新后还有效吗

**有效，而且是自动的。** 已有结论（`codex-update-durability-report.md`）在本面板下依然成立：

- 启动器设置 `CODEX_SPARKLE_ENABLED=false` 冻结当前构建；
- Store 更新后包目录名变化 → 引擎自动重建可写副本（约 3,498 个文件 / ~2.2 GB / 首次约 11 秒）；
- 补丁字面量按正则**重新推导**，不写死；只有**门控补丁**（紫光 + 包身份）验过才报 `PATCHED`；
- 稳态下 `prepare` 耗时 ~0.0–0.2 秒。
- 标签补丁是**失败开放（fail-open）**的：万一某个新版本改掉了 i18n 表结构，
  最坏情况只是**标签退回显示「最高」**，绝不会导致启动失败。

## 7. 回退路径（三层，任选）

```bat
:: 1) 只还原某个版本的可写副本（推荐，务必带 --only）
python %LOCALAPPDATA%\CodexEffortPanel\codex-max-effects-patch.py restore --only 26.915.4065.0

:: 2) 还原补丁引擎本体（去掉 Ultra 标签能力）
copy /y %LOCALAPPDATA%\CodexEffortPanel\codex-max-effects-patch.py.bak-dsh-label %LOCALAPPDATA%\CodexEffortPanel\codex-max-effects-patch.py

:: 3) 还原启动器（回到本次改动之前）
copy /y %LOCALAPPDATA%\CodexEffortPanel\launch-codex-default.cmd.bak-dsh-purple %LOCALAPPDATA%\CodexEffortPanel\launch-codex-default.cmd
```

面板上的「**回退**」按钮等价于第 1 条，并且带确认弹窗、只影响它显示的那个版本。

## 10. 已知限制

1. **英文界面仍显示 `Max`**：asar 补丁是**等长字节替换**，`Max`（3 字节）装不下 `Ultra`（5 字节），
   引擎会记录并跳过。中文（zh-CN）已生效为 `Ultra`。这是等长替换的硬约束，不是 bug。
2. **只有 zh-CN 是「最高」**，zh-HK / zh-TW / ja-JP 原本就是英文/日文 `Max`，未改。
3. 点「启动 Codex」时若 Codex 已在运行，补丁**不会**生效（单实例锁），面板会明确提示。
4. 「回退」按钮出于安全**未做破坏性实点测试**，仅代码审查 + 引擎 `restore --only` 路径验证。
